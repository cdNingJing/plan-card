# Enhanced Knowledge System API - Postman Guide

## Overview

This document provides complete API documentation for Postman usage, including all available endpoints, required headers, request body formats, and response examples.

**Base URL**: `http://localhost:8001` (or your deployment URL)

## Authentication

All endpoints (except root and health) require Bearer token authentication.

### Required Headers for Authenticated Endpoints
```
Authorization: Bearer your_api_token_here
Content-Type: application/json
```

**Note**: The token should be at least 10 characters long. The system will generate a user ID based on your token.

## 2. Content Management Endpoints

### POST /content - Ingest Content
Process and store content in the knowledge system.

**Headers**:
```
Authorization: Bearer your_api_token_here
Content-Type: application/json
```

**Request Body**:
```json
{
  "content": "Your content here - can be text, JSON object, or structured data",
  "content_type": "text",
  "metadata": {
    "title": "Optional title",
    "source": "Optional source",
    "author": "Optional author"
  },
  "collection_name": "my-collection",
  "enable_graph_storage": true,
  "enable_reasoning": false
}
```

**Field Descriptions**:
- `content` (required): Content to process - can be string, object, or array
- `content_type` (required): One of: `text`, `json`, `document`, `structured`
- `metadata` (optional): Additional metadata object
- `collection_name` (optional): Target collection name (defaults to user-specific collection)
- `enable_graph_storage` (optional): Enable Neo4j graph storage (default: true)
- `enable_reasoning` (optional): Enable reasoning capabilities (default: false)

**Example - Text Content**:
```json
{
  "content": "Artificial intelligence is transforming healthcare by enabling early disease detection and personalized treatment plans.",
  "content_type": "text",
  "metadata": {
    "title": "AI in Healthcare",
    "source": "Research Article",
    "category": "technology"
  }
}
```

**Example - JSON Content**:
```json
{
  "content": {
    "name": "Machine Learning Model",
    "type": "Neural Network",
    "accuracy": 0.95,
    "parameters": {
      "layers": 3,
      "neurons": [128, 64, 32]
    }
  },
  "content_type": "json",
  "metadata": {
    "model_version": "1.0",
    "created_by": "data_scientist"
  }
}
```

**Response Example**:
```json
{
  "request_id": "12345678-1234-5678-9012-123456789012",
  "status": "success",
  "message": "Content processed successfully",
  "processing_time": 2.45,
  "summary": {
    "vector_storage": {
      "chunks_stored": 1,
      "collection_name": "collection_user_1234",
      "embedding_dimensions": 1536
    },
    "graph_storage": {
      "chains_stored": 5,
      "entities_extracted": 12
    }
  },
  "chunk_ids": ["chunk_1", "chunk_2"],
  "entity_count": 12
}
```

## 3. Search Endpoints

### POST /search - Search Content
Perform hybrid vector-graph search on the knowledge system.

**Headers**:
```
Authorization: Bearer your_api_token_here
Content-Type: application/json
```

**Request Body**:
```json
{
  "query": "machine learning applications in healthcare",
  "limit": 10,
  "collection_name": "my-collection",
  "filters": {
    "category": "technology",
    "source": "research"
  },
  "include_graph_context": true,
  "score_threshold": 0.7
}
```

**Field Descriptions**:
- `query` (required): Search query text
- `limit` (optional): Maximum results (1-100, default: 10)
- `collection_name` (optional): Target collection (defaults to user's collection)
- `filters` (optional): Additional metadata filters
- `include_graph_context` (optional): Include graph context (default: true)
- `score_threshold` (optional): Minimum relevance score (0.0-1.0, default: 0.0)

**Example - Basic Search**:
```json
{
  "query": "artificial intelligence",
  "limit": 5
}
```

**Example - Advanced Search with Filters**:
```json
{
  "query": "neural networks deep learning",
  "limit": 15,
  "filters": {
    "category": "research",
    "year": "2024"
  },
  "include_graph_context": true,
  "score_threshold": 0.8
}
```

**Response Example**:
```json
{
  "request_id": "12345678-1234-5678-9012-123456789012",
  "query": "machine learning applications in healthcare",
  "total_results": 8,
  "processing_time": 1.23,
  "results": [
    {
      "id": "chunk_123",
      "content": "Machine learning is revolutionizing healthcare...",
      "score": 0.92,
      "metadata": {
        "title": "AI in Healthcare",
        "source": "research_paper",
        "category": "technology"
      },
      "graph_context": {
        "related_entities": ["AI", "Healthcare", "Diagnosis"],
        "relationships": ["AI -> enables -> Diagnosis"]
      }
    }
  ]
}
```

### GET /search/suggestions - Search Suggestions
Get search query suggestions.

**Headers**:
```
Authorization: Bearer your_api_token_here
```

**Query Parameters**:
- `query`: Base query string
- `limit`: Number of suggestions (default: 5)

**Example URL**: `/search/suggestions?query=machine learning&limit=3`

**Response Example**:
```json
{
  "query": "machine learning",
  "suggestions": [
    "machine learning artificial intelligence",
    "machine learning machine learning",
    "machine learning data analysis"
  ],
  "timestamp": "2024-01-15T10:30:00Z"
}
```

## 4. Collection Management Endpoints

### POST /collections - Create Collection
Create a new collection for storing content.

**Headers**:
```
Authorization: Bearer your_api_token_here
Content-Type: application/json
```

**Request Body**:
```json
{
  "collection_name": "my-new-collection",
  "vector_size": 1536,
  "description": "Collection for storing research papers"
}
```

**Field Descriptions**:
- `collection_name` (required): Name of the collection
- `vector_size` (optional): Vector dimension size (default: 1536)
- `description` (optional): Collection description

**Response Example**:
```json
{
  "collection_name": "my-new-collection",
  "user_id": "user_1234",
  "status": "created",
  "description": "Collection for storing research papers",
  "vector_size": 1536,
  "timestamp": "2024-01-15T10:30:00Z"
}
```

### GET /collections - List Collections
List all collections accessible to the current user.

**Headers**:
```
Authorization: Bearer your_api_token_here
```

**Request Body**: None

**Response Example**:
```json
{
  "user_id": "user_1234",
  "collections": [
    "collection_user_1234",
    "my-collection",
    "research-papers"
  ],
  "total_count": 3,
  "timestamp": "2024-01-15T10:30:00Z"
}
```

### DELETE /collections/{collection_name} - Delete Collection
Delete a collection and all its content.

**Headers**:
```
Authorization: Bearer your_api_token_here
```

**Path Parameters**:
- `collection_name`: Name of the collection to delete

**Request Body**: None

**Response Example**:
```json
{
  "collection_name": "my-collection",
  "user_id": "user_1234",
  "status": "deleted",
  "timestamp": "2024-01-15T10:30:00Z"
}
```

## 5. Error Responses

All endpoints may return error responses in the following format:

**401 Unauthorized**:
```json
{
  "error": "HTTPException",
  "message": "Invalid authentication token",
  "timestamp": "2024-01-15T10:30:00Z"
}
```

**400 Bad Request**:
```json
{
  "error": "ValidationError",
  "message": "content_type must be one of: ['text', 'json', 'document', 'structured']",
  "timestamp": "2024-01-15T10:30:00Z"
}
```

**404 Not Found**:
```json
{
  "error": "HTTPException",
  "message": "Collection not found",
  "timestamp": "2024-01-15T10:30:00Z"
}
```

**500 Internal Server Error**:
```json
{
  "error": "InternalServerError",
  "message": "Internal server error",
  "details": {
    "error_type": "DatabaseConnectionError"
  },
  "timestamp": "2024-01-15T10:30:00Z"
}
```

## 6. Postman Collection Setup

### Environment Variables
Create a Postman environment with these variables:

```
base_url: http://localhost:8001
auth_token: your_api_token_here
```

### Global Headers
Set these headers in your Postman collection:

```
Authorization: Bearer {{auth_token}}
Content-Type: application/json
```

### Quick Test Sequence

1. **Health Check**: `GET {{base_url}}/health`
2. **Create Collection**: `POST {{base_url}}/collections`
3. **Add Content**: `POST {{base_url}}/content`
4. **Search Content**: `POST {{base_url}}/search`
5. **List Collections**: `GET {{base_url}}/collections`

---

## 7. Rate Limits

- **Content ingestion**: 100 requests/hour per user
- **Search operations**: 1000 requests/hour per user  
- **Admin operations**: 50 requests/hour per user

---

## 8. Additional Notes

- The system uses OpenAI embeddings for vector search
- All content is processed through both vector (Qdrant) and graph (Neo4j) databases
- User isolation is enforced - users can only access their own collections
- All timestamps are in UTC ISO format
- Request IDs are generated for tracking and debugging
- The API supports both synchronous and asynchronous processing

For interactive API documentation, visit: `http://localhost:8001/docs`
